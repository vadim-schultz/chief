## Goal

After this chapter, the `stack-python` pack exists with three service skills for the Python API stack. Each skill gives the agent working rules for the library and says where to look up current docs. The skills do not claim an MCP server where none was verified.

   - `test_stack_python_pack_names_no_project_identifier`: the identifier scan finds no hit.
   - `test_stack_python_skills_pass_contract`: the C2a checker finds no violation.
   - `test_litestar_claims_no_official_docs_server`: the `litestar` skill says `MCP: none verified` for its docs. It may name the community `litestar-mcp` plugin only as a plugin that exposes routes, and not as a documentation source.

   Confirm each fails before the pack exists.

3. **Green.** Write the pack. Facts for each skill:

   - **litestar.**
     - Docs index: `none verified`. The search found no official `llms.txt`.
     - MCP: `none verified` as a documentation source. The community plugin `litestar-mcp` (cofin) exposes route handlers as MCP tools. A project adds it only when it wants MCP endpoints. It is not a documentation server.
     - Docs: https://litestar.dev. Use the docs-lookup order from C2a. Context7 is optional (D8).
     - Working rules: an ASGI application. Describe request and response bodies with Pydantic models. Use dependency injection for database sessions. Test handlers with the test client. Keep route handlers thin, and move logic to services.

   - **sqlalchemy-alembic.**
     - MCP: `none verified`. Docs index: `none verified`.
     - Docs: https://docs.sqlalchemy.org and https://alembic.sqlalchemy.org.
     - Working rules: write SQLAlchemy 2.0 style (`select()` and `Session.execute`). The psycopg 3 URL scheme is `postgresql+psycopg://`. In Alembic, review each autogenerated revision before you commit it. Never edit a revision that has been applied to a shared database. Keep one head per branch. Run `alembic upgrade head` as part of the deploy step. A vector column needs the `vector` extension, and the migration creates it with `CREATE EXTENSION IF NOT EXISTS vector`.

   - **pydantic.**
     - MCP: `none verified`. The vendor publishes an LLM documentation index, in a short form and a full form, at https://pydantic.dev/docs/validation/latest/integrations/llms/. The page says the files cannot be used natively by some IDEs, and it suggests an MCP server as a workaround. Record the index as the docs source, and do not claim an MCP server.
     - Working rules: use the v2 API (`model_validate`, `model_dump(exclude_none=True)` for partial writes). Use `pydantic-settings` for environment settings. Use a discriminated union with `TypeAdapter` for one of several models.
