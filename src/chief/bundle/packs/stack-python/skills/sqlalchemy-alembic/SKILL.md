# SQLAlchemy and Alembic

SQLAlchemy maps Python code to a database. Alembic keeps the schema in versioned revisions. Use these rules for both. For version numbers and new APIs, follow the docs-lookup skill in the stack-docs pack.

## Working rules

- Write SQLAlchemy 2.0 style. Build a statement with `select()` and run it with `Session.execute()`, for example `row = session.execute(select(User)).first()`. See https://docs.sqlalchemy.org/en/20/tutorial/data_select.html
- Use the psycopg 3 URL scheme, `postgresql+psycopg://`. Write the credentials as placeholders, for example `postgresql+psycopg://${DB_USER}:${DB_PASSWORD}@${DB_HOST}/${DB_NAME}`. See https://docs.sqlalchemy.org/en/20/dialects/postgresql.html
- Review each autogenerated revision by hand before you commit it. Autogenerate does not detect everything: a table rename appears as a drop and an add, and expression changes are never detected. See https://alembic.sqlalchemy.org/en/latest/autogenerate.html
- Never edit a revision that a shared database has applied. Add a new revision instead.
- Keep one head per branch. Run `alembic heads` to list the heads, and merge two heads with a merge revision. See https://alembic.sqlalchemy.org/en/latest/branches.html
- Run `alembic upgrade head` as a deploy step. It upgrades from the current database revision. See https://alembic.sqlalchemy.org/en/latest/tutorial.html
- A vector column needs the pgvector extension. The number in `vector(3)` is the dimension. The migration enables the extension with `CREATE EXTENSION IF NOT EXISTS vector`. The `IF NOT EXISTS` form issues a notice and does not fail when the extension exists. See https://github.com/pgvector/pgvector and https://www.postgresql.org/docs/current/sql-createextension.html
- Check the current version on the vendor root page before you pin one. The SQLAlchemy root page lists 2.1 as current and 2.0 as legacy. See https://docs.sqlalchemy.org/en/20/
